# Методология

## 1. Калибровка сложности

**Проблема.** Сложность задачи, назначенная вручную, часто не совпадает с реальностью. Нужно исправлять её по ответам учеников, но не гоняться за шумом.

**Правила.**

1. **Пропуски не считаются ошибками.** Попытки с `skipped = true` исключаются из всех расчётов. Если считать их ошибками, сложность завышается.
2. **Минимум данных.** Задача участвует, только если непропущенных попыток больше 10.
3. **Значимость.** Точный двусторонний биномиальный тест: наблюдаемая доля верных против ожидаемой по текущей сложности. Пересчёт только при p < 0.05.
4. **Байесовское сглаживание.** Новая оценка не равна сырой доле верных, чтобы одна неудачная выборка не сломала рейтинг:

   `p_new = (k · p_old + успехи) / (k + n)`

   где `k` — сила априори (в скрипте по умолчанию 10), `n` — число непропущенных попыток.

**Шкала и назначение.** Скрипт работает со сложностью как с ожидаемой долей верных ответов (0..1) и решает отдельную задачу — периодический аудит банка: накопилось ли достаточно ответов и не разошлась ли назначенная сложность с наблюдаемой. Это не механизм подбора задач в реальном времени. Если сложность хранится как рейтинг Elo, переведите её в ожидаемую долю перед запуском:

   `p = 1 / (1 + 10^((рейтинг_задачи − рейтинг_ученика) / 400))`,

   усреднив по ученикам, которые отвечали на эту задачу.

**Формат входа:** `question_id, expected_p, correct, skipped`.

## 2. Поиск дублей

1. **Точные дубли:** текст после нормализации (нижний регистр, без знаков препинания, один пробел).
2. **Перефразированные:** числовой отпечаток — отсортированный набор всех чисел из условия. Две задачи с одинаковыми числами скорее всего об одном и том же.

Отпечаток даёт **кандидатов**. Окончательное решение принимает человек: задачи «25% от 80» и «80% от 25» имеют одинаковый отпечаток, но не являются дублями.

**Формат входа:** `id, text`.

## 3. Классификация по таксономии Блума

Все задачи классифицируются по четырём уровням: `remember`, `understand`, `apply`, `analyze`. Уровень `remember` получился очень малочисленным: задачи с выбором ответа редко проверяют чистое воспроизведение. Это ожидаемо и не является ошибкой разметки.

## 4. Двуязычные пары

Задачи на казахском и русском связаны через `pair_id`. Любое исправление применяется к паре целиком (`WHERE pair_id = ...`), чтобы версии не расходились.

## 5. Автоматизация и ручная проверка

Метод автоматизирует отбор кандидатов, но не решения. Любая правка ответа или текста проходит ручную проверку.
