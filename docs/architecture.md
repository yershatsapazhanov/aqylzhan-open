# Архитектура

Платформа состоит из трёх статических HTML-страниц и одного общего бэкенда на Supabase.

```
 index.html (ученик) ─┐
 teacher.html        ─┼──►  Supabase: Postgres + Auth + RLS + RPC
 parent.html         ─┘            └─ Edge Functions (операции с повышенными правами)
```

## Почему три страницы, а не одна

Каждая роль загружает только свой код. Это быстрее и проще поддерживать, чем одно приложение с ветвлением интерфейса.

## Роли

- **Ученик:** тесты по темам, диагностика, марафон, дуэли, профиль с двумя радарами (поведенческий и по Блуму).
- **Учитель:** классы по коду приглашения, домашние задания, статистика ученика и класса.
- **Родитель:** привязка ребёнка по коду, отчёт, подтверждение email.

## Принципы безопасности

1. **Правила живут на сервере.** Скрытая кнопка в интерфейсе не защита. Проверки (например, подтверждён ли email) выполняются внутри RPC-функций.
2. **Явный `REVOKE EXECUTE`.** В Supabase новые функции получают права для `anon` и `authenticated` напрямую, поэтому одного `REVOKE ... FROM PUBLIC` недостаточно.
3. **Тестирование под реальной ролью.** Проверки RPC выполняются с `SET LOCAL role authenticated` и подставленными `request.jwt.claims`. Блок `DO $$` без этого работает от суперпользователя и обходит все права.
4. **Минимум данных о детях.** Согласия фиксируются отдельной таблицей, версия документа привязана к согласию.

## Что не публикуется

Тела RPC-функций экономики и дуэлей, политики доступа к данным пользователей, секреты Edge Functions и сам банк задач.
